# Portable Codex launcher primitives

This directory contains reusable local developer-experience primitives for
running Codex against Git worktrees. Repository-specific launchers should keep
their policy in a thin adapter and delegate common behavior here.

The scripts in this directory support Bash 3.2 on macOS and common GNU/Linux
environments. They require `git`; the runner also requires the configured
Codex executable, and the fork-session workflow requires `jq`.

## Scripts

- `run.sh` launches Codex for the current worktree or an explicit worktree.
  It applies per-worktree cache directories, configured `--add-dir` paths,
  optional model and reasoning settings, and RTK environment defaults.
- `new-worktree-launcher.sh` creates a Git worktree and a generated launcher
  with no default session. Run the launcher once, then pin the resulting
  session ID.
- `session.sh pin` updates a generated launcher with a session ID.
- `session.sh fork` forks the source launcher's pinned session, detects the
  new child session, and creates another generated launcher pointing to it.
- `launcher-lib.sh` provides sourceable launcher rendering, metadata, and
  configuration helpers.
- `requirements.sh` provides sourceable dependency checks and installation
  hints.

## Configuration

`run.sh` reads the optional Bash-compatible configuration fragment at:

```text
${XDG_CONFIG_HOME:-$HOME/.config}/codex/launcher.env
```

Set `CODEX_LAUNCHER_CONFIG` to use another file. Supported configuration
values include:

```bash
CODEX_LAUNCHER_ADD_DIRS=("$HOME/src/example/repo")
CODEX_LAUNCHER_MODEL=""
CODEX_LAUNCHER_REASONING_EFFORT=""
CODEX_LAUNCHER_SANDBOX="workspace-write"
# Defaults to ${XDG_CACHE_HOME:-$HOME/.cache}/codex when omitted.
# Set an absolute private path only when an override is required.
# CODEX_LAUNCHER_CACHE_ROOT="/absolute/private/codex"
CODEX_LAUNCHER_USE_RTK="1"
```

The `USE_RTK` environment variable overrides `CODEX_LAUNCHER_USE_RTK` for a
single run. By default, Codex retains its normal state home (`~/.codex`), so
pinned sessions remain resumable from launchers and direct Codex invocations.
Set `CODEX_HOME` in the configuration or environment only to use another Codex
state home. The per-worktree cache home is absolute, current-user-owned, and
non-symlinked; the launcher enforces mode `0700` before invoking Codex. It is
intentionally not added with `--add-dir`, which is reserved for agent-writable
workspace roots.

## Direct usage

Run the shared runner from a repository checkout:

```bash
codex/launcher/run.sh --worktree-dir "$PWD" --
```

Create a worktree launcher through a repository-specific adapter:

```bash
codex/launcher/new-worktree-launcher.sh \
  --worktree-dir "$HOME/src/example-feature" \
  --branch feature/example \
  --generator-marker '# generated by example DX tooling' \
  --session-command scripts/dx/launcher-session.sh \
  --runner-relative-path scripts/dx/codex
```

Pin a session after the first run:

```bash
codex/launcher/session.sh \
  --generator-marker '# generated by example DX tooling' \
  pin \
  --launcher "$HOME/.local/bin/codex-example-feature" \
  --session-id SESSION_ID
```

Fork a pinned launcher:

```bash
codex/launcher/session.sh \
  --generator-marker '# generated by example DX tooling' \
  fork \
  --launcher "$HOME/.local/bin/codex-example-feature" \
  --target-launcher "$HOME/.local/bin/codex-example-feature-2"
```

`--runner-relative-path` must remain within the repository. Generated
launchers are intentionally repository-specific and should invoke the local
adapter, not hard-code this shared checkout's absolute path.
